#### SerDes RX 路径的模拟电路详解

```
信号从PCB走线来 → SerDes RX pin

┌──────────────────────────────────────────────────────────────┐
│  RX 模拟前端 (Analog Front End)                                │
│                                                                │

│  ────┬──────────────────────────────────────                   │
│      │  眼图几乎闭合（像一团模糊的椭圆）                          │
│      ▼                                                         │

│  │      │   可编程增益：0-12dB                                   │
│  └──────┘                                                      │
│      │                                                          │

│      │                                                          │
│      ▼                                                          │

#### SerDes 模拟设计的挑战

```
┌────────────────────────────────────────────────────────────────┐
│               SerDes 模拟设计五大挑战                            │
│                                                                │
│  ① 抖动 (Jitter)                                               │
│     时钟的边沿在时间上随机晃动                                    │
│     来源：电源噪声、热噪声、串扰                                  │
│     后果：CDR误判，BER上升                                       │
│     要求：UI(unit interval)内抖动 < 0.3UI                       │
│           25Gbps: 1UI = 40ps, 抖动预算≈12ps                     │
│                                                                │
│  ② 信号完整性 (Signal Integrity)                                │
│     PCB的损耗：FR4在25GHz时 ~20dB/inch                           │
│     → 需要用CTLE+DFE来补偿                                      │
│     → 但补偿过度也会放大噪声                                     │
│                                                                │
│  ③ 串扰 (Crosstalk)                                            │
│     相邻lane之间电磁耦合                                        │
│     封装、PCB走线、连接器都会有串扰                                │
│     缓解：差分信号本身抗共模、屏蔽设计                             │
│                                                                │
│  ④ 电源噪声 (Power Supply Noise)                                │
│     数字电路开关产生大量电源噪声                                  │
│     模拟SerDes对电源噪声极其敏感                                  │
│     缓解：独立的LDO供电、深N阱隔离、去耦电容                        │
│                                                                │
│  ⑤ PVT变化 (工艺/电压/温度)                                     │
│     芯片在不同温度、不同电压下电气特性不同                          │
│     缓解：自适应校准(BG参考、温度补偿、自动调节)                   │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 PCS 层 — 数字与模拟的交界

```
SerDes 出来的并行数据
    │
    ▼
┌──────────────────────────────────────────────┐
│              PCS (Physical Coding Sublayer)   │
│                                               │
│  RX方向 (数据从SerDes来 → 给MAC)              │
│  ┌─────────────────────────────┐              │
│  │ ① 64B/66B 解码              │              │
│  │   66bit块 → 判断同步头:     │              │
│  │   ├→ 01 = 数据块，直接取64bit数据          │
│  │   └→ 10 = 控制块，解析控制码               │
│  │       0x78 = SFD(帧开始)                   │
│  │       0xFF = 空闲(IDLE)                    │
│  │       0x9C = 终止(TERM)                    │
│  │       其他 = 错误序列                        │
│  ├─────────────────────────────┤              │
│  │ ② RS-FEC 解码 (可选)       │              │
│  │   Reed-Solomon (528, 514)  │              │
│  │   每528bit数据块里纠正最多7个symbol错误      │
│  │   需要FEC对齐标志(AM锁相)                  │
│  ├─────────────────────────────┤              │
│  │ ③ 去扰码 (Descrambler)     │              │
│  │   把发送端加的伪随机序列去掉                  │
│  │   目的是恢复原始数据                          │
│  ├─────────────────────────────┤              │
│  │ ④ Lane去偏斜 (Deskew)      │              │
│  │   多条lane之间因为走线长度不同有相位差         │
│  │   用对齐标记(AM)做相位对齐                    │
│  │   把4条lane的数据重新拼成完整的流             │
│  └─────────────────────────────┘              │
│              │                                  │
│         64位并行数据 @ 390.625MHz               │
│              │                                  │
│  TX方向 (数据从MAC来 → 给SerDes)               │
│  ┌─────────────────────────────┐              │
│  │ ① 64B/66B 编码              │              │
│  │   根据MAC送来的数据和控制信号                 │
│  │   加同步头 → 拼成66bit块                     │
│  ├─────────────────────────────┤              │
│  │ ② RS-FEC 编码 (可选)       │              │
│  │   加冗余校验位用于接收端纠错                   │
│  ├─────────────────────────────┤              │
│  │ ③ 加扰 (Scrambler)         │              │
│  │   加伪随机序列防止连续0/1导致DC不平衡         │
│  ├─────────────────────────────┤              │
│  │ ④ Lane去偏斜 (Alignment)   │              │
│  │   插入对齐标记(AM)用于接收端对齐              │
│  └─────────────────────────────┘              │
│              │                                  │
│         到 SerDes TX 的并行数据                  │
└──────────────────────────────────────────────┘
```

## 五、交换矩阵（Switch Fabric）

### 5.1 为什么需要交换矩阵？

```
场景：
  64口 × 100G交换机
  每个端口都能以100G线速收发
  → 总带宽 = 64 × 100G × 2(收+发) = 12.8Tbps
  → 需要12.8Tbps的互联带宽在端口之间搬运数据

  不可能让每个端口都直接连到所有其他端口（64×64交叉线=太恐怖）
  → 需要一个内部的"交换矩阵"来高效互联
```

### 5.2 几种交换矩阵架构对比

```
┌─────────────────────────────────────────────────────────────────┐
│  ① Crossbar (交叉开关) — 最常用                               │
│                                                                  │
│        ┌───┐                                                    │
│  Port0─┤   ├──Port0                                              │
│        │   │                                                     │

│        │   │                                                     │

│        └───┘                                                    │
│                                                                  │

│  适用：N ≤ 32（中等规模）                                         │
│                                                                  │
│  ② 多级Crossbar (Clos网络) — 大规模交换机用的                   │
│                                                                  │
│      ┌─[Stage1]─┬─[Stage2]─┬─[Stage3]─┐                        │
│      │ ┌────┐   │ ┌────┐   │ ┌────┐   │                         │
│  Port0─┤CB0 ├───┤CB0 ├───┤CB0 ├──Port0│                        │
│  Port1─┤    │   │    │   │    ├──Port1│                          │
│      │ ├────┤   │ ├────┤   │ ├────┤   │                         │

│      │ └────┘   │ └────┘   │ └────┘   │                         │
│      └─────────┴──────────┴──────────┘                          │
│                                                                  │

│                                                                  │

│  适用：家用5-8口交换机                                            │
│                                                                  │
│  ④ Mesh (网格) — 芯片内部多Core互联                             │
│                                                                  │
│     Core0 ── Core1                                              │
│       │  \      │                                                 │
│       │   \     │                                                 │
│     Core2 ── Core3                                              │
│                                                                  │
│  优点：高可靠(多条路径)                                           │
│  缺点：面积大(每个节点要有路由功能)                                │
│  适用：多Core芯片内部的Core间互联                                 │

### 6.3 CPU 收发包的硬件路径

```
CPU发送一个ARP回复包：

CPU写DMA描述符 → DMA从DDR读包数据 → 
DMA把包写入共享包缓冲区 → 
包做特殊标记(tx_from_cpu=1) → 
送入流水线Stage 2 → 跳过MAC学习 → 
查端口路由(走CPU指定端口) → 从目标端口发出

CPU接收一个ICMP超时报文：

流水线Stage 4检测到TTL=0 → 
包被标记(trap_to_cpu=1) → 
Stage 5把包复制一份到CPU队列 → 
DMA把包从共享缓冲区搬到DDR → 
CPU从DDR读到内存 → CPU组装ICMP超时报文

关键设计：发包不走MAC学习、不走路由查找（因为CPU已经知道发给谁了）
```

### 7.2 PLL 树

```
外部参考时钟 (25MHz / 156.25MHz 晶振)
    │
    ▼
┌────────────────────────────────────────────┐
│             主 PLL (LC-VCO)                 │
│  输出: 4GHz (VCO频率)                       │
│  分频:                                       │
│  ÷4  → 1.0GHz  → 流水线核心                 │
│  ÷5  → 800MHz  → CPU域                      │
│  ÷10 → 400MHz  → MAC域                      │
│  ÷2  → 2GHz    → DDR PHY                    │
└────────────────────────────────────────────┘

每个 SerDes Quad 有自己的独立 PLL：
┌────────────┐  ┌────────────┐  ┌────────────┐
│ SerDes    │  │ SerDes    │  │ SerDes    │
│ PLL Quad0 │  │ PLL Quad1 │  │ PLL Quad2 │
│ 25GHz     │  │ 25GHz     │  │ 25GHz     │
└────────────┘  └────────────┘  └────────────┘

为什么要独立PLL？
  因为SerDes需要的时钟抖动要求极高(~1ps)
  数字电路的电源噪声会破坏时钟质量
  所以SerDes用自己的PLL（屏蔽了数字噪声）
```

### 7.3 跨时钟域同步策略

```

│                     │          │                     │
│  wdata ────────▶    │          │    ┌────▶ rdata     │
│  wclk  ────────▶    │ ASYNC   │    │                │
│  wrst_n ──────▶    │  FIFO   │    │                 │
│  winc ─────────▶    │ (深度16) │    │                 │
│                     │          │    │                 │
│  gray_wptr ─────────┼─▶ sync ─┼────┘                 │
│                     │          │  rclk  ────────▶     │
│  gray_rptr ─────────────────▶│  rr-┐st_n ──────▶     │
│                      │ sync │  renc ────────▶     │
│                      └───────┘                     │
│                      │          │                     │
│    (格雷码同步)       │          │                     │
└─────────────────────┘          └─────────────────────┘

为什么用FIFO+格雷码？
  → 避免跨时钟域信号的亚稳态
  → 格雷码每次只变1bit → 即使亚稳态最多影响1个指针值
  → 保证数据不丢不重
```

### 8.2 低功耗技术

```
芯片级别省电技术：
┌────────────────────────────────────────────────────┐
│  ① 时钟门控 (Clock Gating)                         │
│     Stage没活干时 → 关掉它的时钟                    │
│     省电效果：流水线逻辑功耗降30-50%                │
│                                                     │
│  ② 电源门控 (Power Gating)                         │
│     不用的SerDes Quad → 彻底断电                    │
│     省电效果：SerDes模拟功耗降~100%(不用时)         │
│                                                     │
│  ③ DVFS (动态电压频率调整)                          │
│     负载低 → 降低主频 + 降低电压                     │
│     频率从1GHz → 500MHz, 电压从0.8V→0.65V           │
│     功耗理论降：(0.5/1)×(0.65/0.8)² ≈ 33%          │
│                                                     │
│  ④ 自适应均衡 (Adaptive EQ)                         │
│     短线缆/好信道 → 降低CTLE/DFE强度                 │
│     省电效果：每lane SerDes省~30%                   │
│                                                     │
│  ⑤ 动态TCAM关断                                     │
│     ACL/路由条目少 → 只激活部分TCAM块                │
│                                                     │
│  合计省电潜力：典型工作负载下省40-60%                 │
└────────────────────────────────────────────────────┘
```

## 十、总览总结

### 完整数据流（一句话串起来）

```
物理信号(差分对) 
  → SerDes (CDR恢复时钟+均衡+串转并) 
    → PCS (64B/66B解码+FEC纠错+解扰)
      → MAC RX (帧定界+CRC校验+写入包缓冲区)
        → 包处理流水线 (解析→查MAC→查路由→重写头)
          → Traffic Manager (队列+调度)
            → MAC TX (CRC重算+前导+SFD+IFG)
              → PCS (编码+加扰+FEC)
                → SerDes TX (并转串+驱动)
                  → 物理信号(差分对) 

从电信号进去到电信号出来 → 延迟: ~400-600ns
中间经过了：模拟 → 数字 → 模拟 的完整旅程
```

### 一句话总结架构

```
SerDes(模拟) 
  → PCS/MAC(数字高速) 
    → 包处理流水线(数字核心) 
      → 交换矩阵(数据搬运) 
        → Traffic Manager(队列调度) 
          → MAC/SerDes(出去)
                ↑
           CPU(控制平面, 慢速)
           DDR(片外存储, 超大容量)
           TCAM(并行查找, 高功耗)
           SRAM(片上表项, 快速访问)
```
